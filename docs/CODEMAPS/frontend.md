`App.tsx` (295) also mounts the pending-sync drain trigger (cold start + AppState→active,
30s throttle) — see backend.md "Pending-sync queue".

Business logic lives in extracted `lib/*.ts` modules (ideaSaveFirst, saveFirstOutcome,
captureErrorDecision, attachmentPersistence, promoteIdeaOnDisk, noteReprocess,
enhanceProse, wysiwygSave, vaultImageInsert, settingsForm, modelBrowser, shareHelpers,
retrospective, askExplainer, checklist…)
— screens are mostly UI. Prefer extending those modules over adding inline screen logic.

`AskScreen` is the clearest current example of that split: ordering, budget packing,
citation resolution, the "top N of M" line and markdown normalization all live in the
pure `lib/retrospective.ts`, so the screen holds only the async pipeline and render.

`enhanceProse` is the ⋮-sheet "Enhance" action: it splits frontmatter + the `# Title` off
a saved note, sends only the prose to `dispatcher.enhanceProse`, and re-attaches them
around the result (stamping `enhanced:`). It sits beside `noteReprocess` rather than
inside it because that module's flows all require a paired binary on disk; Enhance needs
none, which is why it works on a text-only journal entry. Routing honours
`Settings.enhanceProviderId` — a dedicated, usually stronger provider that takes
precedence over the active one (the inverse of `visionProviderId`'s rung).

## Native capture surfaces (`apps/mobile/plugins/*.js`)
Two always-on entry points that live **outside** React: a persistent notification
(`withCaptureNotification.js`) and a home-screen widget (`withCaptureWidget.js`).
Both fire the same `carnet://` deep links as the in-app FAB — pure RemoteViews /
Notification APIs, no JS bridge, nothing to refresh.

**These plugins ARE the native source.** `apps/mobile/android/` is gitignored and
fully regenerated by `expo prebuild`, so the emitted Kotlin and layout XML are
build output — editing them directly is invisible to git and reverted on the next
prebuild. Change the JS strings in the plugin instead.

The widget is resizable **4×1 ↔ 2×2** (`widget_capture.xml` /
`widget_capture_2x2.xml`, same four button ids so the provider binds
layout-agnostically). Sizing takes two paths because minSdk is 24: a
size→RemoteViews map on API 31+, and `onAppWidgetOptionsChanged` below that.

Verification ladder — each rung catches what the one above cannot:
`scripts/verify-notification-and-widget-prebuild.sh` (files emitted, ids match)
→ CI `mobile-android` (Kotlin compiles) → a real device (layout actually
inflates; an unsupported RemoteViews view fails only here).
